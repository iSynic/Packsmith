# Readable legacy extraction: beta 4 revision 1

The GUI now defaults to readable Windows names and visible `.rsrc` AppleDouble files. Archive > Legacy extraction options retains escaped names and the earlier `._` preservation mode. Choices are session-local and do not alter Classic Mac export. Existing worker clients that omit the new options retain their original behavior.

Readable names replace Windows-invalid characters with underscores; original decoded/raw components and entry IDs remain in the mapping. Collision planning uses original components so different folders with the same readable name remain distinct. Authored `.rsrc` names, duplicate files, case variants and Windows device names are preserved with safe substitutions/suffixes.

`.rsrc` mode omits empty placeholders for resource-only files and folder metadata sidecars. Genuine empty files are kept. File resource forks and available FinderInfo remain in AppleDouble containers; full available folder FinderInfo stays in the report. Mapping `output_written` distinguishes a nominal data name from a file actually created. Details/results describe the actual companion and output policy. Available explicit folder modification dates are applied after writes; the previous classic timezone/DST interpretation limitation remains.

The local `hax-13.hqx` regression passed in both output modes. The main folder contains 44 items with readable/`.rsrc` output versus 84 with escaped/`._` output. Every logical file's data/resource bytes and file FinderInfo match between the modes, and the source archive is unchanged. This is a filesystem-output regression, not a new independent classic-Mac oracle claim.

Final checks passed: 22 worker tests, 14 legacy tests, 14 Classic Mac export tests, five new output-option tests, native model/controller/UI checks, eight GUI/recovery scenarios and branding/previous-name recovery. The new native dialog tests cover cancellation, accepted choices, accessible names, focus restoration and explicit policies passed to a real worker. New worker regressions cover readable collisions, literal separators, resource-only/genuine empty files, folder dates, selected extraction, invalid policies, corruption, cancellation and crash cleanup. Qt/engines/toolchains remain pinned; the legacy helper is unchanged. No new full Narrator or independent emulator qualification is claimed.
